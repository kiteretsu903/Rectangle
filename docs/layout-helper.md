# Layout Helper

Layout Helper fills an existing layout after a Rectangle snap. It has no top-of-screen layout selector. The initiating window remains in place while one empty region shows a window picker.

## Behavior

All sequences use reading order: left to right in a row, then top to bottom. Skip the initiating cell and compatible occupied cells.

| Initiating layout | Remaining regions |
| --- | --- |
| Left/right half | Opposite half |
| Top/bottom half | Opposite half |
| Any corner quarter | Other quarters in top-left, top-right, bottom-left, bottom-right order |
| Single third | Other equal thirds |
| Two-thirds or three-fourths at an edge | Complementary third or fourth |
| Center half or center two-thirds | Separate leading and trailing strips |
| Single fourth | Remaining fourths |
| Sixths | Remaining cells in reading order |
| Eighths, ninths, twelfths, sixteenths | Remaining cells, with dense-grid option enabled |

Orientation-aware actions follow Rectangle's portrait geometry; explicitly vertical thirds stay vertical. Achieved split boundaries and configured gaps determine the destinations, rather than assuming every split remains 50/50. An already arranged rectangular union of cells, such as a right-half window beside a top-left quarter, is retained as occupied. Mere overlap from a floating window does not count.

Center three-fourths, corner-third variants, maximize, arbitrary sizing, restore, movement/display actions, and bulk tiling/cascading do not initiate assistance. Corner-third variants need a separately agreed complementary layout.

Candidates are normal, non-minimized, non-hidden windows in the on-screen inventory on the destination display. Excluded apps, Rectangle panels, system dialogs, full-screen windows, sheets, and the to-do sidebar are filtered. Ambiguous window-ID matches are omitted. The picker initially orders app groups by their frontmost candidate in WindowServer stacking order. Windows from the same bundle identifier stay adjacent, with a PID fallback when no identifier exists. Group order and within-app order stay fixed during the sequence; new windows append within their app group. Selected/retained windows disappear from later steps.

Click to place a candidate. Known non-resizable or oversized candidates are disabled. Failed placement attempts return the candidate to its previous frame and leave the picker open with an explanation. Escape, close, or clicking outside ends the sequence without undoing completed placements. A new Rectangle action or manual drag cancels pending assistance. Space changes, display changes, screen sleep, session deactivation, and changes to retained windows dismiss it. No candidates ends the sequence; a single candidate still requires a click.

## In-app example and thumbnail permission

**Snap Areas → See example…** shows the bundled Layout Helper example, rendered from the actual picker with sample windows. It illustrates selecting a window for the remaining region after snapping another window. It contains no personal window content.

macOS uses Screen Recording permission for still window-thumbnail access as well as recording APIs. Layout Helper uses in-memory still images for these previews, does not save them to disk, and does not capture audio. Without permission, its icons and window titles remain usable. The example and Window Divider do not require permission.

## Window Divider (independent feature)

With **General → Window Divider** enabled (off by default), Rectangle remembers one full-height left/right or full-width top/bottom pair per display after an ordinary snap or a completed two-cell picker sequence. This includes complementary unequal splits. Hover within 24 pt horizontally and 54 pt vertically of the shared edge's midpoint to reveal an 18 × 76 pt input panel with a narrow neutral handle. For a top/bottom pair, the input panel and hover region rotate to 76 × 18 pt and 108 × 48 pt, with an up/down cursor. Drag along the split axis to move only the handle and a guide spanning the pair while both windows remain at their original frames. A pointer-transparent overlay contains two blurred skeleton panels sized to the proposed destinations, separated by the configured gap. Each uses the main picker's full-screen UI material, behind-window blending, active state, neutral outline, corner fallback, and presentation inset (12 pt, or 8 pt for narrow regions, bounded for tiny sizes). Outer padding and the divider gutter remain transparent; the guide and handle remain visible. Release fixes the skeletons at the proposed split and hides the handle. The native live-blur guide stays visible while both windows receive their destination frames. Window Divider does not capture screenshots or request Screen Recording permission, and works with Layout Helper disabled. After acknowledged, stable placement, the overlay fades away over 120 ms. This divider transition uses covered placement independently of the ordinary window animation option. The pointer's initial offset is retained so grabbing the handle does not jump the proposed split. Outer edges, cross-axis geometry, and the configured gap remain fixed.

Known minimum widths or heights clamp movement along the split axis. Reported and learned sizes come from the shared `WindowSizeConstraints` store. If an app omits its minimum size, the controller learns a clamp along the split axis from AX readback, recomputes both destinations, and retains the verified limit for subsequent gestures and other snapping paths. Failed placement or rollback does not publish a learned divider minimum. The shrinking side is written first, followed by the expanding side. Within each window, moving left or up precedes growth; shrinking precedes moving right or down. This avoids a display-edge clamp caused by growing the right-hand window while it is still at its old position. A refused or inconsistent write attempts to restore both windows to the last accepted pair, then stops the gesture. AX does not offer an atomic two-window resize, so application response time can affect smoothness or prevent rollback.

Double-click returns the split to equal sizes, subject to each app's minimum. It uses the same covered placement and reveal sequence; the handle itself tracks the pointer without easing. Escape or an interruption during dragging discards the proposed split without moving either window. After release has begun, interruption stops further writes and reconciles the actual pair; it cannot undo an application request that is already in flight. A single controller owns both placements and the reveal gate. It preserves existing restore rectangles and records each accepted result for subsequent Rectangle actions. Known width or height minimums constrain the handle preview. A previously unknown minimum may still require a first resize to discover; later gestures reuse the learned boundary.

The handle hides while the picker is open, either window is absent from the current on-screen inventory, or another normal window covers either member. A changed display work area or incompatible moved/resized member invalidates the pair when checked. Fresh WindowServer reads, live AX reconciliation of compatible splits, and a short settlement grace interval avoid discarding a pair because of a pre-resize inventory sample. An outside click, Escape, another Rectangle command, or a Space change interrupts current movement. Sleep, session deactivation, display changes, configuration import, and app termination clear the controller. Pairs remain in memory only: after restarting Rectangle, arrange the pair again. This does not create a system window group.

The controller polls at 120 ms while pairs exist, querying a fresh WindowServer inventory only near a handle or during interaction. Pointer updates only change the proposed divider coordinate, panel position, and guide drawing; there are no window writes or movement timer during dragging. Release and double-click send one changed AX attribute at a time, acknowledging it before sending the next attribute or adjusting the other window. This accommodates apps that coalesce asynchronous size and position requests. Each acknowledgment requires 50 ms of stable readback and has a 600 ms deadline. A stable size change that stops short of the requested size can establish an unreported minimum; an unchanged or refused request cannot. Rollback uses the same sequential acknowledgment path. The reveal gate then requires both accepted frames to remain within 1 pt for at least 50 ms, sampling every 25 ms. A 600 ms gate timeout dismisses the overlay and discards the stalled pair. Only overlay opacity animates, over 120 ms; interrupted settlement and fade callbacks cannot revive it. The live backdrop uses AppKit visual effects, so no screenshot or recording permission is involved. Pair history is updated during completion cleanup. Input and workspace changes interrupt movement. The panel is nonactivating and does not take keyboard focus. It exposes an accessibility press action for equal sizes. The divider uses its own `windowDivider` Boolean preference; neither Layout Helper nor fitting needs to be enabled.

## Simplified waiting-area appearance

Only the current destination contains candidate previews. Every other remaining empty destination has a plain blurred panel; occupied windows stay visible. Each full-region input window contains an inset visual panel: 12 pt on each edge, 8 pt when the shorter dimension is below 320 pt (further bounded for exceptionally tiny regions). This presentation inset does not affect snap destinations or any other snapping shade.

The waiting panel and preview cards use a light-grey 1 pt outline. Corners use centralized presentation fallbacks of 18 pt on macOS 26+ and 10 pt on older systems, bounded by card dimensions. These approximate the OS-era window shape; the current deployment SDK exposes no native-window-radius accessor, and exact system matching is not established. Previews have an explicit opaque backing and full-opacity images, a 40 pt icon/title header with an 18 pt icon and 13 pt title, and no preview shadow. Foreground content is a sibling of the blur view, preventing inherited vibrancy from altering preview colours. ScreenCaptureKit is also configured with `shouldBeOpaque`, no captured window shadows, and BGRA output. There is no default heading or bottom caption. An error message appears only after placement failure. The close × remains in the upper-right corner, and missing capture permission gets a small footer link.

Preview layout starts at a shared 36% of each source window's dimensions, with a 120 pt longest-side floor for small sources and a 420 × 260 pt image cap. It preserves aspect ratio and candidate order, packs centered rows with 16 pt gaps, and centers the group vertically when it fits. It tries shared scales of 100%, 90%, 80%, 70%, then 60%; at the floor it scrolls instead of continuing to shrink. Without capture permission, compact icon/title tiles use the same row-packing algorithm. Source dimensions arrive with the inventory, so images can load without rearranging the layout. Mouse-triggered assistance has no selection ring or coloured hover border. Keyboard-triggered assistance starts with a 2 pt neutral-grey selector. Arrow keys and Tab navigate eligible controls; Enter chooses the focused preview. Using the keyboard reveals the selector after a mouse-triggered snap, and clicking switches it off. Previews have 20 pt side/bottom padding within the blur, plus a reserved top area for ×.

Clicking ×, Escape, any background gap, another empty blurred region, or the clear outer inset margin dismisses the entire remaining sequence without undoing completed placements. Background mouse-down events inside these overlay windows are consumed. Preview controls, including disabled previews, and scrollbars retain their own input handling. Clicking an already occupied application outside the overlays retains the existing outside-dismiss behavior.

## Settings and capture

The Snap Areas pane exposes:

- `layoutHelper`: off by default; opt-in for drag snaps. The existing optional-Boolean encoding remains compatible (1 on, 2 off, 0/unset now off).
- `layoutHelperKeyboard`: opt-in for keyboard and menu snaps, with a short delay after completion so repeated shortcuts can settle.
- `layoutHelperDenseGrids`: opt-in for grids with eight or more cells.

**General** separately exposes `windowDivider` (**Window Divider**) and `fitBesideSnappedWindows` (**Fit remaining space**), both off by default. Grey helper text below each checkbox states: “Left/right and top/bottom pairs only.” All three feature switches are independent.

ScreenCaptureKit still thumbnails use macOS 14+ APIs after a successful permission preflight. The picker remains usable with app icons and Accessibility titles when capture is unavailable. Enabling the Layout Helper checkbox when permission is missing opens an explanation with **Enable Previews** and **Use Icons and Titles**. After **Enable Previews** is chosen, an asynchronous ScreenCaptureKit shareable-content request asks macOS for access without capturing an image or audio. The flow waits for that request to finish before opening System Settings; repeated clicks cannot start overlapping requests. Request success or the error domain/code is logged for troubleshooting. **Enable window previews…** in both settings and the picker uses the same flow. Settings displays the permission status and refreshes it when Rectangle becomes active again. No permission dialog appears automatically during dragging or merely opening settings.

When access remains unavailable after the request, the flow opens **System Settings → Privacy & Security → Screen & System Audio Recording** and explains how to enable Rectangle. If Rectangle is absent, the guidance tells the user to click **+** and select Rectangle in Applications. macOS may require reopening the app after a permission change. Already-authorized users are not prompted again; choosing icons never requests access or opens Settings. The six permission-flow tests inject all system actions, so they never change actual permissions. The pane name and manual-add fallback follow [Apple's guidance](https://support.apple.com/guide/mac-help/allow-apps-to-use-screen-and-audio-recording-mchl592e5686/mac).

Capture failures retain an existing thumbnail or the icon fallback. A shared in-memory cache retains at most 32 MiB of decoded image bytes, measured as `bytesPerRow × height`, with explicit least-recently-used eviction. This is not a cap on total process memory: visible cards and temporary capture buffers can retain additional memory. A window key includes the window ID, process ID, process launch time, and source dimensions. Closed windows are evicted on inventory checks; entries expire after 120 seconds, with an idle cleanup timer and memory-pressure eviction. No images are written to disk.

Cached previews are installed before the picker is ordered onscreen. Images less than two seconds old are reused without recapture; older retained images display while refreshing. At most two actual capture calls run concurrently across queue changes, even while older calls finish after dismissal. The visible viewport is prioritized, scrolling updates the pending order, and duplicate requests are coalesced. The window inventory for capture is shared for two seconds. Failures use a five-second retry delay. There is no continuous idle capture or live-video stream.

Entering an eligible snap area triggers a single debounced prefetch batch after 120 ms. Leaving/changing the area or releasing the drag removes pending work; the cache survives for subsequent steps. Disabled Layout Helper, revoked permission, sleep/session deactivation, screen-lock notifications, and memory pressure stop pending work and discard results as appropriate. Screen-capture requests remain permission-gated; cache operations never prompt for permission.

## Architecture

- `LayoutHelperLayout`: pure top-left-coordinate partition geometry, gap application, reading order, and matching occupied rectangular unions.
- `LayoutHelperManager`: completion-triggered sequence, generation-token cancellation, window inventory, placement/readback, restore history, and asynchronous still capture.
- `LayoutHelperPanel` / `LayoutHelperSurface`: nonactivating input surfaces, visually inset blur, opaque previews, background dismissal, accessible controls, and capture opt-in. `LayoutHelperPreviewLayout` handles deterministic source-size-based row packing separately from destination geometry.
- `LayoutHelperPreviewStore`: byte-budgeted cache, two-slot capture queue, stale-image refresh, drag prefetch, and stable app-group ordering.
- `WindowDividerManager`: pair registration, hover visibility, gesture ownership, covered placement, stable-frame reveal, and history cleanup. `WindowDividerGeometry` / `WindowDividerResize` keep geometry and verified two-window writes separate from AX and UI. `WindowDividerPanel` draws and handles the nonactivating divider.
- `LayoutHelperPermission`: shared explanation, explicit opt-in, permission request, and System Settings guidance; system calls are injectable for tests.
- `WindowManager`: sends completed action geometry, including no-op snaps and animation completion. Stale completion tokens cannot reopen a cancelled picker.
- `SnappingManager`: exempts pointer events inside the picker from drag handling; a new manual grab cancels assistance before settling an older animation.
